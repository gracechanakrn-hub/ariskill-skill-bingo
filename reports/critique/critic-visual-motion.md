Checks that passed (recorded so the next stage does not re-do them):

- **BR-17 / Gate 3, capability and rank:** every Soul is drawn in one 200 px viewBox, one glow radius, one outline weight; `PALETTES` share one luminance band (test "palettes are equal-value"); constellation glyphs are one size and only weight *order* changes placement; `badge` is a separate parameter; `validateSoulConfig` rejects platform/role/rank/size fields; WebGL sprites are pushed with tint `1,1,1,alpha` (`webgl2.js pushSprite`), Canvas 2D never tints; the only scale change is the transient, identical entrance pulse (1.0 -> 1.12 -> 1.0). Winners' Souls are not moved, enlarged or recoloured in Winner (scene-spec 10, confirmed in `scene.js`). Stage/admin never show per-person skills.
- **Inclusivity of the cohort:** `soul-cohort-sheet.png` - no skin-tone ramps (pastel light/nature hues, near-white face disc), no hair/lashes/clothing/body-curve cues, six silhouettes of equal height, palette names are light/nature words; alt text template excludes Platform/Role/rank (tested).
- **Safe zone and hierarchy:** 65/35 split is a hard canvas boundary (`.galaxy` sized to its region, panel opaque `--color-bg-elevated`, 32 px inner margin); no effect crosses x = 1248 in any capture. Public hierarchy is correct in all three states: eyebrow -> headline 96 px -> hero numeral 128 px -> QR 420 px; Playing: draw number 64 px -> kind chip (icon + label + colour) -> skill name 96 px with `fitText` down to 48 px -> matched count 48 px -> pacing; Winner: "Bingo!" 192 px -> round -> names 64 px (48 px when > 4).
- **Motion ranges:** add/remove 150 ms, board glow 780 ms, lock 400 ms, match 300 ms, line trace `iteration-count: 1`, winner burst 1000 ms (public override 400 ms) with text at 280 ms, Soul reveal 2000 ms with skip, Float 3-2-1 on server clock, entrance 2200/600/1200 ms, orbit 0.02 rad/s max, camera drift 1.5 % / 40 s, shake forbidden. Every `.m-*` class has a reduced-motion twin in both the media query and the `[data-reduced-motion="true"]` block. Only `.m-orbit`, `.m-pulse-soft` (0.42 Hz) and the Soul glow breath (4.8 s, removed under reduced motion) repeat - plus the `ui-pulse` noted in VM-06.
- **Flash risk:** the draw ripple is +10 % star brightness over 350 ms, the entrance pulse +8 %, the winner halo <= 35 % opacity and a single bloom; no full-field luminance swings, no saturated red. PEAT/Harding run is still owed by the rehearsal (motion-spec 8, step 2).
- **Fatigue over 2 h:** ambient bed -24 dBFS RMS, 7 s seamless loop, ducked only by `bingo`/`float_launch`; twinkle amplitudes 8-15 % at 5-9 s periods; orbit period 60 s; the celebration guard prevents re-bursts on reconnect (verified by `reconnect.test.js` and `motion.test.js`).
- **Provisional-token labelling:** `tokens.css` header, art-direction 9 map, `.theme-venue` scale and OD-12 are all explicit; contrast/CVD tests green.

## 3. Strengths to preserve

- The Soul system is genuinely equal-by-construction; the tests, not just the prose, enforce BR-17. Keep the "badge outside the config" rule and the neutral fallback.
- Public panel composition: opaque safe zone, hero numerals at 128-192 px, `fitText` for long skill names and many co-winners, previous-winners footer that survives every state.
- Celebration guard + `replay`/epoch discipline is applied on all four surfaces (`shouldCelebrate`, `setReplaying`, `setConnectionEpoch`), so reconnects never re-celebrate - this is the hardest motion requirement and it is done properly.
- Stage insights tiles use icon + label + colour consistently, suppress small cohorts with an explicit note, and use tabular numerals throughout.
- Reduced-motion coverage is complete at the CSS level, and the in-app toggle mirrors the OS preference.
- Sound: one tonal centre, error cue is the only descending motif, ducking limited to two cues, captions for every accepted play.
