# Asset and audio integration (workflow stage 6.6 / 13.6)

Owner: asset-integration-agent. Run `run-20260922-113339`. Zero third-party code; Node >= 24 and Python 3 + numpy (audio only).

This document explains how the asset pipeline is validated and consumed: the manifest validator, the generated typed asset map, preload lists, missing-asset fallback rules, the license/provenance policy, the budgets that are enforced, how to add an asset, and the CI command.

## 1. Files

| Path | Role |
|---|---|
| `assets/manifest/assets.yaml` | Canonical manifest for scene + Soul assets (workflow 5.2 fields). Generated by `build-scene.js` and `build-souls.js`; never hand-edited. |
| `assets/manifest/audio.yaml` / `audio.json` | Canonical audio manifest and its byte-equivalent JSON twin (the browser fetches the JSON). Generated by `build-audio.py`. |
| `tools/assets/validate-manifest.js` | Validator: CLI (`--root`, `--json`, `--quiet`) and library `validateManifests({ root, budgets, checkAssetMap, checkUiKit })` returning `{ ok, problems: [{ severity, check, path, detail }], summary }`. Exit 1 on any critical/major. |
| `tools/assets/build-asset-map.js` | Generates `packages/ui/asset-map.js` from the manifests (`--check` verifies it is current). |
| `tools/assets/build-all.js` | Runs `build-scene.js`, `build-souls.js`, `python3 tools/assets/build-audio.py`, `build-asset-map.js`, then validates. `--check` only verifies outputs are current (nothing is written). |
| `packages/ui/asset-map.js` | Generated, frozen, typed asset map plus helpers (`assetUrl`, `fallbackUrl`, `soulSpriteUrls`, `preloadListFor`, `withFallback`, `checkIntegrity`). Node-importable. |
| `tools/assets/test/integration.test.js` | node:test suite for everything above (runs on a disposable copy of the tree for mutation cases). |

## 2. How validation works

`validateManifests` reads both manifests and walks `assets/`. Every problem is `{ severity, check, path, detail }` with severity `critical` (integrity/provenance violation), `major` (blocks the gate), `minor` (warning; human gate item) or `info`. `ok` is true only when there is no critical and no major problem.

Checks per `assets.yaml` entry:

| Check id | What it verifies |
|---|---|
| `field.missing`, `field.version`, `field.vector`, `field.number`, `field.approvedBy`, `id.format` | All workflow 5.2 fields present (`id kind source_file source_format runtime_file runtime_format fallback_file fallback_format version checksum license generator_script bounds pivot triangle_count texture_memory_bytes lods approved_by`), semver version, `[x, y, z]` bounds/pivot, snake_case id. |
| `id.duplicate` | No duplicate ids within a manifest (`id.crossManifest` is a minor for an asset id that collides with an audio cue id). |
| `license.disallowed` (critical) | `license` must be `internal-original` (also the header `license_default` and the audio manifest/cue licenses). |
| `format.placeholder` | `source_format` / `runtime_format` / `fallback_format` must be concrete: `selected_after_stack_verification`, `tbd`, `todo` and empty values are rejected. |
| `generator.missing`, `source.missing`, `source.pointer` | `generator_script` and `source_file` exist (audio `source_file#/cues/<id>` pointers must resolve inside `assets-src/audio/cues.json`). |
| `file.missing`, `file.location` | `runtime_file` exists and lives under `assets/` (audio under `assets/audio/`). |
| `checksum.format`, `checksum.mismatch` (critical) | `checksum` is `sha256:<64 hex>` and equals the file's SHA-256. |
| `bytes.mismatch` | `texture_memory_bytes` (assets) / `bytes` (audio) equal the file size; audio `totals.bytes` equals the sum. |
| `fallback.missing`, `fallback.undeclared` (minor), `fallback.sameAsRuntime` (minor) | A declared `fallback_file` exists. `kind: model` / `kind: sprite` without a fallback is a minor warning (the client applies the built-in rule below). |
| `lods.malformed`, `lods.missing`, `lods.runtimeAbsent` (minor) | `lods` is an array of unique existing paths. |
| `approval.pending` (minor) | One warning per manifest counting entries with `approved_by: null` (gate item for the human reviewers; the summary carries the numbers). |

Checks per audio cue (`audio.json`, cross-checked against `audio.yaml` via `audio.twin`): required fields `id kind runtime_file checksum bytes duration_s license generator_script source_file source_format runtime_format version sample_rate channels bit_depth loop preload audiences caption approved_by`; `audio.header` (RIFF/WAVE, PCM format tag 1, 22 050 Hz, mono, 16-bit, consistent chunk sizes and manifest fields); `audio.duration` (data-chunk duration equals `duration_s` within 1 ms and does not exceed `max_duration_s`); `audio.loop` (`0 <= start < end <= samples`, only on `audio-loop` cues, required for them); `audio.peak` (peak not above the manifest ceiling); `audio.audience` / `preload.audience` (preload apps are a subset of `participant admin public stage` and of the cue's audiences); `audio.caption`; `provenance.missing`; `preload.uiKitSync` (`PRELOAD_BY_APP` in `packages/ui/audio.js` equals the manifest-derived sets).

Tree checks: `manifest.orphan` (every file under `assets/` except `assets/manifest/`, `README*`, `sheet.html` and `.gitkeep` must be listed as a `runtime_file`, `fallback_file` or LOD), the budgets in section 3, and `assetmap.missing` / `assetmap.stale` (`packages/ui/asset-map.js` must equal a fresh generation).

## 3. Budgets enforced

| Budget | Limit | Scope | Check id |
|---|---|---|---|
| All runtime assets | 6 MB (6 291 456 B) | `assets/**` except `assets/manifest/` | `budget.assets` |
| Audio | 1.6 MB counted as 1600 KiB (1 638 400 B), the same number as `budgets.max_total_bytes` in `audio.yaml`; the lower of the two applies | `assets/audio/**` | `budget.audio` |
| Single file | 1.2 MB (1 258 291 B) | any runtime file | `budget.singleFile` |
| Soul SVG | 6 KB (6 144 B) | every `assets/souls/**/*.svg` (full, simple, dot, thumbnail) | `budget.soulSvg` |
| Scene data | 120 KB (`scene-spec.md`) | `assets/scene/**` | `budget.sceneData` |
| One-shot cue | `budgets.max_oneshot_bytes` from `audio.yaml` (120 KB) | `kind: audio-oneshot` | `budget.audioOneshot` |
| Bundle per app | 600 KB | `apps/<app>/**` excluding `test/` (`app.empty` info while an app has no files) | `budget.app` |

Current use (validator summary): assets 1.19 MB, audio 672 KB, scene data 45 KB, largest file 302 KB (`ambient_galaxy.wav`), largest Soul SVG 4.1 KB. Budgets can be overridden programmatically (`validateManifests({ budgets: { ... } })`) for tests; the CLI always uses the table above.

## 4. Typed asset map (`packages/ui/asset-map.js`)

```js
import { ASSETS, assetUrl, fallbackUrl, soulSpriteUrls, preloadListFor, withFallback, checkIntegrity } from '/packages/ui/asset-map.js';

ASSETS.scene.config        // '/assets/scene/scene-config.json'   ASSETS.scene.nebula, .starfield[3], .orbitRings, .sha256.*
ASSETS.scene.defaults      // embedded copy of scene-config.json (built-in defaults when the fetch fails)
ASSETS.souls.cohort        // '/assets/souls/cohort.json'; .cohortDir, .thumbnailDir, .fallbackDir, .suffix, .count, .seeds
ASSETS.audio.bingo         // { url, bytes, durationS, kind, loop, priority, rateLimitMs, duck, audiences, preload: { participant, admin, public, stage }, caption, copyKey, sha256 }
ASSETS.entries[id]         // every assets.yaml entry: { kind, url, format, fallbackUrl, fallbackFormat, sha256, bytes, lods }
ASSETS.manifestVersion     // '1.0.0'; ASSETS.generatedAt is always null (deterministic); ASSETS.sha256OfManifests.{assets.yaml, audio.yaml, audio.json, combined}
ASSETS.budgets, ASSETS.fallbackRules
```

- `assetUrl(id)` -> URL for an asset entry id or audio cue id, `null` if unknown. `fallbackUrl(id)` -> declared fallback or `null`.
- `soulSpriteUrls(seed)` -> `{ full, simple, dot, thumbnail }` for any Soul seed (cohort or live participants: the paths follow the generator's naming rule).
- `preloadListFor(app)` -> cue ids flagged for that app, priority descending then manifest order (e.g. participant: `bingo, float_launch, draw_reveal, draw5_unlock, cell_match, float_countdown`). Same sets as `PRELOAD_BY_APP` in `packages/ui/audio.js` and section 6 of `docs/audio/sound-spec.md`; the validator and the test fail if they drift.
- `withFallback(url, fallbackUrl)` -> `{ url, fallback, candidates, next(current), onError(event) }`; attach `onError` to an `<img>` / `<source>` error event and it swaps `src` to the fallback exactly once.
- `checkIntegrity(fetchFn?)` -> fetches five small assets (scene config, orbit rings, cohort index, the smallest cue, one Soul sprite), hashes them with `crypto.subtle` and returns `{ ok, checked, mismatches, errors, skipped }`. Never throws; `skipped` is set when fetch or `crypto.subtle` is unavailable. Run it once at app start under `?debug=1` or in QA, not on every load.

The whole object is deeply frozen. The module has no `window`/`document` access, so it imports in Node for tests.

## 5. Preload lists

Source of truth: the `preload` array of each cue in `audio.yaml` (from `assets-src/audio/cues.json` policy). Derived views that must stay identical: `PRELOAD_BY_APP` in `packages/ui/audio.js`, `preloadListFor(app)` in the asset map, and the table in `docs/audio/sound-spec.md` section 6.

| App | Preload right after `createAudioManager()` | Lazy on first request |
|---|---|---|
| participant | bingo, float_launch, draw_reveal, draw5_unlock, cell_match, float_countdown | registration_ready, soul_reveal, error_soft |
| public | bingo, float_launch, draw_reveal, draw5_unlock, draw_leadin, ambient_galaxy | error_soft, reconnect |
| stage | bingo, float_launch, draw_reveal, ambient_galaxy | reconnect, error_soft |
| admin | bingo, draw_reveal | draw_leadin, error_soft, reconnect |

Scene/Soul preload: the public and stage apps load `ASSETS.scene.config` first, then the starfield layers, orbit rings and nebula in parallel; Soul sprites are rendered client-side from `config` by `soul-renderer.js` (the cohort files are review/test fixtures and thumbnails), so nothing else needs preloading.

## 6. Missing-asset fallback rules

| Asset | Rule | Where it is implemented |
|---|---|---|
| Soul sprite (full SVG) | `full -> simple -> dot`. The dot (24 px static disc, `<fallbackDir>/<seed>-dot.svg` or `renderSoulSvg(config, { detail: 'dot' })`) always renders; a Soul is never omitted or replaced by a generic placeholder. Use `withFallback(urls.full, urls.dot)` or the LOD list in `ASSETS.entries[id].lods`. | Public/stage renderers; `soul-renderer.js` renders from `config` so a missing file only affects fixtures |
| Audio cue (missing, decode error, autoplay denied, no AudioContext) | Silent + caption: `AudioManager.play()` returns `false`, marks the cue `unavailable` and still emits `onCaption({ id, caption, played: false, reason })`; apps route it to the polite live region / caption chip. No error is shown to employees. | `packages/ui/audio.js` (E14 handling), sound-spec sections 8-9 |
| `scene-config.json` (fetch fails or invalid JSON) | Use `ASSETS.scene.defaults` (an embedded copy of the generated config: safe zone, LOD thresholds, performance levels, reduced motion, entrance timings, fallback order `webgl2 -> canvas2d -> static`). | Public/stage apps |
| Starfield layer / orbit rings JSON | Skip that layer (sky stays valid with the remaining layers); orbit slots come from `soulOrbitSlot()` in the renderer, so `orbit-rings.json` is decorative. | Public/stage apps |
| `nebula.svg` | Paint `ASSETS.scene.defaults.background` (`#0B0F1F`) on the Galaxy viewport. The manifest declares no `fallback_file` for `scene_nebula` (`fallback.undeclared` minor; see handoff note). | Public/stage apps |
| `cohort.json` / thumbnails | Test and review fixtures only; nothing at runtime depends on them. | - |

## 7. License and provenance policy

- Only `internal-original` is allowed (`ALLOWED_LICENSES`). Every runtime asset must be produced by a script in `tools/assets/` from a source in `assets-src/`; the manifest records `source_file`, `generator_script`, `checksum` and `version`. Recorded, sampled, stock, AI-image or third-party material is rejected by `license.disallowed` (critical) and would also fail `generator.missing`/`source.missing`.
- `approved_by` is `null` until a human reviewer (brand owner for scene/Souls, sound sign-off for cues) records their name. The validator reports the counts as a `minor` `approval.pending` per manifest; the gate owner decides whether release proceeds with pending approvals. Approvals are set by re-running the generator with the approval recorded in the source parameters (never by hand-editing the manifest).
- The audio manifest carries a `provenance` statement (`provenance.missing` otherwise).

## 8. How to add an asset

1. Put the editable source under `assets-src/<area>/` (parameters JSON, synthesis recipe, or cohort definition). Never write into `assets/` by hand.
2. Extend the generator in `tools/assets/` (`build-scene.js`, `build-souls.js`, `build-audio.py`, or a new deterministic script that calls `mergeManifest()` from `tools/assets/lib/manifest.js`). The generator must emit every workflow 5.2 field, a concrete `runtime_format`, a `fallback_file` for models/sprites, and the file's SHA-256 and size.
3. Run `node tools/assets/build-all.js`. It regenerates everything, rebuilds `packages/ui/asset-map.js` and validates.
4. Run `node --test tools/assets/test` and fix any budget/orphan problems (an over-budget file is a design change, not a validator exception).
5. Commit the source, the generator change, the regenerated runtime files, both manifests and the asset map together.

## 9. CI / gate command

```sh
npm run assets:validate            # node tools/assets/validate-manifest.js   (exit 1 on critical/major)
node tools/assets/build-all.js --check   # generators are current + asset map current + validate
node --test tools/assets/test      # audio, souls, integration suites
```

`tools/assembly/release-gate.js` already runs `node --test tools/assets/test` under the resilience category, so the integration suite is part of the hard QC gate. `npm run assets:validate` is the command for the assembly step and for CI.

## 10. Compatibility with `tools/assembly/assemble.js`

The assembler parses the manifests with its own minimal YAML reader. Both manifests keep the flat `- key: value` item style it expects, and the asset map is a plain ES module under `packages/ui/` (no secrets patterns, no dependencies). Two behaviours of the assembler's reader are worth knowing when reading its report: it treats `fallback_file: null` as a literal path named `null` (reported as `manifest.fileMissing`), and it does not read `lods`, so the dot and thumbnail SVGs appear as `manifest.orphan` minors there while this validator accounts for them.
